## 1 项目概述

- **产品定位**：个人网站。用大图展示「我的生活方式」「我的作品」与「我写的文章」，文字极少，一眼看懂。
- **目标用户**：访客（朋友、潜在合作方、招聘方）。
- **一句话**：像一本翻开的个人画册，而不是一份简历。
- **当前状态**：骨架 + 首屏页面框架已完成，可本地打开。

## 2 核心功能需求（总览表）

| 模块 | 描述 | 优先级 |
|---|---|---|
| 生活方式 / 关于我 | 简短自我介绍 + 个人生活照（大图） | P0 |
| 作品 | 卡片展示作品（大图 + 标题 + 一行说明 + 链接），如微信读书插件 | P0 |
| 文章（站内托管） | 文章列表 + 每篇独立页面；列表项 = 标题 + 日期 + 一行摘要 | P0 |
| 响应式布局 | 手机优先，平板/桌面自适应 | P0 |
| 站内导航 | 全站统一：左＝品牌「i雅俗共赏」，右＝首页 / 作品 / 文章三链接并列一行，当前页高亮 | P1 |
| 联系方式 | 邮箱 / 社交链接（用户决定是否公开） | P1 |
| 深色模式 | 跟随系统 | P2 |

## 3 详细功能需求

### 3.1 生活方式 / 关于我（P0）
- 顶部：名字/昵称（大字）+ 一句话标语。
- 主体：个人生活照，**大图铺开**，可做成瀑布流/网格。
- 自我介绍：**1–3 句话**，不写长段落。

### 3.2 作品（P0）
- 卡片式：每张卡 = 大图 + 标题 + 一行说明 + 「查看」链接。
- **卡片图可点击**：图片整体用 `<a>` 包住，与「访问官网」指向同一链接，`target="_blank"` 新窗口打开；悬停时图片轻微变淡作为可点提示。
- 首个作品：**微信悦读**（微信读书网页版阅读增强插件）——卡片图 `web/assets/img/works/weread-enhancer.jpg`（宣传图），链接指向官网 `https://wereadapp-32km31c.maozi.io`（`target="_blank"` 新窗口打开）。
- 图片缺失时用占位色块，不留破图。
- 第二张卡：**公众号 · i雅俗共赏**——卡片图 `web/assets/img/works/wechat-qr.jpg`（二维码），点击进入站内文章列表 `articles/index.html`。
- **首页也展示作品**：首页「作品」板块与作品页内容一致（两张卡），首页即可看到作品。
- **卡片图高度**：作品图高度设上限（约为原比例撑满时的一半，桌面约 280px、手机约 200px），图片**按原比例缩放、不裁切、居中**，二维码完整可扫；卡片整体不再过高。

### 3.3 响应式（P0）
- 断点：手机（≤640px，单列）→ 平板（641–1024px，双列）→ 桌面（>1024px，三列）。
- 不允许横向滚动；图片自适应容器，带 `loading="lazy"` 与固定宽高比防跳动。

### 3.4 文章（P0，站内托管）
- **内容来源**：Obsidian 仓库 `个人管理/文章输出/03_已发布/` 的 Markdown 原稿（唯一内容源，网站不反向写回）。
- **列表页**：`web/articles/index.html`，每项 = 缩略图（有图时）+ 标题 + 日期 + 一行摘要，点击进入正文。
- **正文页**：每篇文章 = 一个独立页面 `web/articles/<短名>.html`（短名默认 `a-<标题hash8>`；标题重名时自动加后缀区分），由脚本生成，无需构建。
- **首页入口**：首页「文章」板块展示最近若干篇（标题 + 日期 + 一行摘要），数据由 `assets/js/articles-data.js` 提供、`assets/js/site.js` 渲染（`data-limit` 控制条数，默认 4）。
- **一键同步**：双击项目根 `同步文章.command`（内部调用 `tools/sync_articles.py`）把 Obsidian 的已发布文章搬到网站；仅同步 frontmatter `status: 已发布` 的文章，其余跳过；带关键词可只同步部分（如 `同步文章.command 深圳 跑步`，此时不清理其它旧页）。正文里的公众号导出噪声（点赞 / 在看 / 写留言 / 扫码关注 / 阅读原文 / svg 占位图等）与内部信息（版本管理 callout、题图 / Prompt / 图片来源等注脚）自动过滤；连续分隔线只留一条。
- **插图**：文章插图一并复制进 `web/assets/img/articles/<短名>/` 并压缩（长边 ≤2000px、单张尽量 ≤500KB；仍偏大的图会在同步日志里提示，需在 Obsidian 里换图）；公众号外链图尝试带 Referer 下载本地化，失败则保留原链接。
- **导航**：全站统一顶部导航（见 4 节），并高亮当前页「文章」。
- **正文排版**：正文宽度限制在易读区间（约 34–38em），标题/段落/列表/引用/代码块可读，手机优先。
- **不做**：不做标签 / 分类 / 搜索 / 评论 / 分页（除非后续单独立项）；**不做公众号自动抓取**（个人订阅号无公开接口，抓取不合规且不稳定）。

## 4 UI·UX 需求

- **风格**：极简。少文字、多留白、大图为主。
- **视觉参考**：Peter McKinnon（petermckinnon.com）方向——整面图片拼贴墙、大图说话；**只借鉴版式**，不引入其视差/外部依赖。
- **配色**：主体内容区（生活方式 / 作品）沿用原浅色配色（米白底 + 深字）；**首尾两块例外，同为课件灰 `#393939`、通栏铺开、首尾呼应**——① **首屏（顶部自我介绍）**：深灰底，名字 `#FFFFFF`、标语 `#CCCCCC`、一行简介 `#999999`；② **页脚**＝课件《破除假词》最后一页：通栏深灰底 `#393939`，四行文字颜色依次 `#FFFFFF` / `#888888` / `#CCCCCC` / `#999999`，全粗体；字号按屏幕自适应（不照搬幻灯片固定比例）；字体以系统黑体近似。页脚另附一行站点信息（公众号 · 版权），属幻灯片外必要附加。
- **全站导航**：统一顶部导航，**全站吸顶**。左＝品牌「i雅俗共赏」（可点回首页），右＝「首页 / 作品 / 文章」三个链接**并列一行**，当前所在页加粗高亮。首页的导航**初始在首屏（图片那一栏）下方**，**往下滚动时吸顶到视口顶部**（首屏深灰区随之被划过）；作品页 / 文章页导航同样吸顶。导航下方不画长横线。**字号放大**（品牌约 21px、链接约 17px，手机按屏宽自适应）；**悬停效果**＝文字变深 + 与文字等宽的短下划线从中间展开，当前页下划线常驻。
- **全站页脚**：首页、作品页、文章列表页、每篇正文，**统一使用同一套深灰页脚**（四行寄语 + 一行「公众号 · 版权」站点信息），保证子页面与首页底部一致。
- **分隔线**：去掉板块之间、导航下方的「长横线」，保持画面干净；仅保留必要的细分隔（如文章列表项之间的小短线）。
- **首屏文字**：参考「阮一峰的网络日志」的极简文字样式——不做标签对、不做药丸按钮、不加装饰性小标签；只留「名字 + 一句话标语 + 一行灰字简介」，一行说清「专业 / 职业 / 热爱 / 公众号」。
- **字**：标题大、正文少；中英混排（英文仅用于板块副标等轻装饰）。
- **动效**：克制，只用淡入/轻微位移，不做花哨特效。
- **暗色模式**：跟随系统（P2）。

## 5 技术实现方案

- 纯静态、**零构建、零外部依赖**：原生 HTML / CSS / JS。
- 直接在 `web/` 下放 `index.html` + `assets/`；双击即可预览。
- 文章：`web/articles/index.html`（列表）+ `web/articles/<短名>.html`（正文）；复用 `assets/css/site.css` 的文章排版样式，不新增框架。
- 图片存 `web/assets/img/photos|works/`，入库前压缩（≤500KB，长边 ≤2000px）。
- 反 SDK / 反统计 / 反外链字体。

## 7 成功标准

- 手机与电脑打开都不出现横向滚动，图片清晰且加载不卡。
- 访客 10 秒内看懂「这是谁、在做什么、有什么作品、写了什么」。
- 文章列表可读、每篇正文能正常打开，长文阅读不累眼。
- 全站无第三方依赖、无统计脚本。

## 8 风险与应对

| 风险 | 应对 |
|---|---|
| 生活照体积大、加载慢 | 入库前压缩 + `loading="lazy"` |
| 图片缺失导致破图 | 用占位色块，不用假图 |
| 文章写多后页面难维护 | `tools/sync_articles.py` 一键从 Obsidian 同步（固定命名 `a-<hash8>` + 统一模板），列表页与首页数据自动重生成 |
| 隐私泄露 | 不写住址/电话，公开信息须用户确认 |
| 文字写多、违背"简洁" | 自我介绍限 1–3 句，超出就删 |
